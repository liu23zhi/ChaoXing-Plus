## 扩展诊断日志

扩展自动向已配置的 TiKuHelper 服务回传结构化诊断日志，管理员可在 WebUI 查看或关闭。弹窗仅显示服务地址与管理状态，没有个人开关。未配置服务地址、密钥或尚无扩展设备身份时不会上传；正式服务使用 HTTPS，本机调试可用回环 HTTP。

日志沿用现有扩展设备 ID；每次浏览器启动或扩展重新加载会开始新的日志文件，打开页面或后台 worker 被唤醒不会换文件。事件仅包含版本、类型、时间、耗时、次数；不记录网页地址、题目、答案或控制台原文。网络暂时离线时只有限重试，不阻塞正常使用。

纯扩展仅沿用设备标识；使用自有 EXE 打开的独立浏览器复用同一宿主设备标识，并区分宿主为该浏览器分配的会话标识。原生 C 首页只回传自身完成授权、准备交付时与题库成功同步的一条固定事件；Node 宿主只回传自身已授权会话的启动和配置事件。这不是第三方考试已经开始的证明。普通访问密钥不能作为考试启动或日志凭据。日志接口本身不登记设备、不创建或续期脚本会话，也不采集外部考试客户端内部事件。

项目文档和开发清单见 [TikuDoc](https://github.com/liu23zhi/TikuDoc)，本地入口 `../TikuDoc/ChaoXing-Plus/TASKLIST.md`。

## 联合 CI 与人工验收

每个发往 `main` 的 PR 以及合并后的 `main` 都运行[同一个工作流](https://github.com/liu23zhi/ChaoXing-Plus/actions/workflows/ci.yml)。不按浏览器/客户端路径跳过检查。最终的 **三模式联合门禁** 只有在以下检查全部成功时才通过；失败、取消或跳过都不能当作通过。

| 模式 | 自动验证的第一方行为 |
| --- | --- |
| 普通扩展 | 用打包的 MV3 扩展在真实 Chromium 上验证设备标识、启动分档、重试与后台唤醒。 |
| EXE 多浏览器 | 在三个隔离的真实浏览器资料中传入同一宿主设备及各自浏览器标识，确认分档不串；Windows 自有计数夹具与实际服务端共同核对 3 个浏览器占 3 个名额、正常退出后保留 1 个。 |
| 考试模式 | 自有启动器以无操作回调验证授权边界；实际服务校验专用短租约，普通令牌不能替代。日志不续租、不计费、不登记设备。 |

三种模式共用固定版本的 TiKuHelper 控制器、临时 SQLite 和回环服务，检查账号与启动文件隔离；Windows 另有本机 WinHTTP 验证。源码作业保留类型检查、扩展构建和对列明的第一方源码的分组覆盖率阈值，不把浏览器渲染或原生进程计入 Node 行覆盖率。

**真实第三方客户端只做人工验收。** Actions 不下载或运行第三方客户端、访问真实账号或读取用户数据。人工结果单独记录对应提交、授权环境、验收人、日期及结论；未验收就标记「未执行」。CI 通过不等于这部分已通过。
